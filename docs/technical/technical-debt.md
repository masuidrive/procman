# 技術的負債リスト

このドキュメントは、@masuidrive/procmanプロジェクトで認識されている技術的負債と、その対応優先度をまとめています。

最終更新: 2025-08-05

## 優先度: 高

### 1. CLIの実装が不完全

**現状:**
- 基本的なコマンドのみ実装
- 多くのコマンドがスタブ状態
- エラーハンドリングが不十分

**影響:**
- ユーザビリティの低下
- E2Eテストの制限

**対応案:**
- 各コマンドの完全実装
- 統一的なエラーハンドリング
- ヘルプシステムの充実

**関連ファイル:**
- `src/cli/index.ts`
- `tests/e2e/cli.e2e.test.ts`

### 2. Windows環境での名前付きパイプ実装

**現状:**
- 名前付きパイプの実装が部分的
- 権限管理が不完全
- エラーハンドリングが不十分

**影響:**
- Windows環境での動作不安定
- クロスプラットフォーム互換性の問題

**対応案:**
- Windows固有のパイプ実装の完成
- 適切な権限設定
- プラットフォーム別テストの追加

**関連ファイル:**
- `src/daemon/named-pipe-server.ts`
- `src/daemon/named-pipe-client.ts`

## 優先度: 中

### 3. メモリリーク対策の強化

**現状:**
- イベントリスナーの解放漏れの可能性
- 長時間実行時のメモリ使用量増加
- リソース管理の一貫性不足

**影響:**
- 長時間実行時の安定性
- システムリソースの枯渇

**対応案:**
- WeakMapを使用したリソース管理
- 自動クリーンアップ機構の実装
- メモリ使用量の監視強化

**関連ファイル:**
- `src/daemon/resource-manager.ts`
- `src/process-manager/process-monitor.ts`

### 4. ログローテーション機能の未実装

**現状:**
- ログファイルサイズの制限なし
- 古いログの自動削除なし
- ログアーカイブ機能なし

**影響:**
- ディスク容量の圧迫
- ログ管理の手間

**対応案:**
- サイズベースのローテーション
- 時間ベースのローテーション
- 圧縮アーカイブ機能

**関連ファイル:**
- `src/services/log-manager.ts`

### 5. 設定ファイルのマイグレーション

**現状:**
- 設定フォーマットの変更に対応なし
- 後方互換性の考慮不足

**影響:**
- アップグレード時の問題
- 設定ファイルの手動修正が必要

**対応案:**
- バージョン管理システム
- 自動マイグレーション機能
- 設定検証の強化

**関連ファイル:**
- `src/config/config-loader.ts`
- `src/config/config-validator.ts`

## 優先度: 低

### 6. パフォーマンス最適化

**現状:**
- プロセス監視の頻度が固定
- ログバッファリングの最適化不足
- IPC通信のオーバーヘッド

**影響:**
- 大規模環境でのCPU使用率
- レスポンスタイムの遅延

**対応案:**
- 適応的な監視頻度
- バッファサイズの動的調整
- メッセージバッチング

### 7. TypeScriptの厳格性

**現状:**
- 一部で`any`型の使用
- 型定義の不完全な箇所
- ジェネリクスの活用不足

**影響:**
- 型安全性の低下
- リファクタリングの困難さ

**対応案:**
- 段階的な型の厳格化
- ユーティリティ型の活用
- 型推論の改善

### 8. テストの実行速度

**現状:**
- E2Eテストが遅い（特にWindows）
- 一部の統合テストでタイムアウト
- 並列実行の最適化不足

**影響:**
- 開発効率の低下
- CI/CDの実行時間

**対応案:**
- テストの並列化強化
- モックの適切な使用
- テストデータの最小化

### 9. テストコードの改善（レビューフィードバックより）

**現状:**
- エラーアサーションが文字列マッチングに依存
- マジックナンバー（5000ms、1024*1024等）が散在
- 一部で重複するintegrationテストが存在

**影響:**
- エラーメッセージ変更時にテストが失敗
- 環境による不安定性（flaky test）
- テスト実行時間の増加

**対応案:**
- エラーコードベースのアサーションに変更
- タイムアウトと定数を設定ファイルに外出し
- 重複テストの削除

**関連ファイル:**
- `tests/boundary/*.test.ts`
- `tests/integration/*.test.ts`

## 対応済み

### ✅ テスト戦略の見直し（Phase 1-4で完了）

## メンテナンス方針

1. **新規開発時**
   - 技術的負債を増やさない
   - 既存の負債を可能な限り解消

2. **定期的なレビュー**
   - 四半期ごとに負債リストを更新
   - 優先度の見直し

3. **負債解消の時間確保**
   - スプリントの20%を負債解消に割り当て
   - 大規模な負債は専用のスプリントで対応

このリストは定期的に更新され、プロジェクトの健全性を維持するための指針として活用されます。
