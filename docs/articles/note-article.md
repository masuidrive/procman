# AIと一緒にコードを書く時代に、なぜ新しいプロセス管理ツールを作ったのか

## あの日、Claude Codeが動かなくなった

2025年のある日、いつものようにClaude Codeと一緒に開発していた私は、奇妙な現象に遭遇しました。

「コード生成が終わらない...」

30分待っても、1時間待っても、Claude Codeは何も返してきません。最初はClaude Code自体の不具合かと思いましたが、調べてみると原因は意外なところにありました。

```bash
$ pm2 logs
```

このコマンドです。pm2のログストリーミングが終了しないため、Claude Codeはずっとログの出力を待ち続けていたのです。

## Vibe Codingという新しい世界

私が実践している「Vibe Coding」について、少し説明させてください。

これは2024年後半から2025年にかけて登場した、AIと人間が協調してコードを書く新しい開発スタイルです。詳細な仕様書を書く代わりに、自然言語で「こんな感じのアプリを作りたい」という雰囲気（vibe）を伝えると、AIが実装してくれるのです。

私は[ticket.sh](https://github.com/masuidrive/ticket.sh)というCoding Agent向けのチケット管理システムも開発しており、日々この新しい開発スタイルを実践しています。

しかし、既存のツールはAIエージェントの存在を想定していません。人間が使うことを前提に設計されているため、AIにとっては扱いにくいのです。

## 「ないなら作ればいい」

エンジニアの性でしょうか。問題があれば解決したくなります。

pm2は素晴らしいツールですが、10年以上の歴史があり、多機能で複雑になっています。開発環境で使うには機能が多すぎるし、AIエージェントには扱いにくい。

他のツールも検討しましたが、namespaceのような必要な機能が実装されていなかったり、やはりAIフレンドリーではありませんでした。

「じゃあ、作るか」

そう決めたのが、Procman開発の始まりでした。

## 10日間の格闘

正直に言います。「Claude Codeがポンコツで、片手間とはいえ10日もかかってしまった」のです。

最初の3日間は、Claude Codeとの対話に苦労しました。プロンプトを工夫し、指示を明確にし、時には手動でコードを修正し...。でも、この苦労が後の財産になりました。

### Day 1-3: 基本設計とClaude Codeとの格闘

最初はClaude Codeに全体像を理解してもらうのに苦労しました。「デーモンプロセスとCLIクライアントを分離して、IPCで通信する」という構造を、何度も図を描いて説明しました。

### Day 4-6: メモリリーク地獄

Node.jsのEventEmitterは便利ですが、リスナーの解放を忘れるとメモリリークします。長時間稼働するデーモンプロセスでは致命的です。

ここでUncle Bob（Robert C. Martin）の教えを思い出しました。「Disposableパターン」です。EventCleanupHelperクラスを作り、すべてのリスナーを追跡して確実に解放する仕組みを実装しました。

```typescript
class EventCleanupHelper {
  // すべてのリスナーを追跡
  track(emitter, event, listener) { ... }
  
  // 一括解放
  async dispose() { ... }
}
```

たった40行のコードですが、これがProcmanの安定性の要となりました。

### Day 7-9: テストとの戦い

t_wada氏のテスト哲学「境界値テストを重視せよ」に従い、徹底的にテストを書きました。特にメモリ制限の境界値テストは重要でした。

```typescript
test('500MBのプロセスが400MB制限で再起動されるか')
test('399MBのプロセスが400MB制限で再起動されないか')
```

### Day 10: ついに完成

最後の日、すべてのテストがグリーンになった瞬間の感動は忘れられません。Claude Codeも「All tests passed!」と喜んでくれました（そう見えました）。

## 学んだこと

### 1. AIの限界を理解し、補完する

Claude Codeは強力ですが、万能ではありません。人間が適切にガイドし、適切なツールを用意することで、初めてその真価を発揮します。

### 2. シンプルイズベスト

pm2のような多機能ツールも必要ですが、特定の用途に特化したシンプルなツールにも価値があります。Procmanは開発環境とAIエージェントに特化することで、独自の価値を生み出しました。

### 3. プロンプトエンジニアリングの重要性

この開発を通じて、CLAUDE.mdというプロンプト集が大幅に改善されました。AIとの対話方法、指示の出し方、エラーの解釈方法など、多くのノウハウが蓄積されました。

## コミュニティへの恩返し

オープンソースコミュニティから多くを学んできた私にとって、Procmanの公開は小さな恩返しです。

特に、これからVibe Codingを始める人たちの助けになれば嬉しいです。AIと一緒に開発することは、最初は戸惑うかもしれません。でも、適切なツールがあれば、驚くほど生産的になれます。

## 使ってみてください

もしあなたが：
- Claude CodeやCursor、GitHub Copilotを使っている
- 複数のサービスを同時に開発している
- pm2が複雑すぎると感じている
- Vibe Codingに興味がある

なら、ぜひProcmanを試してみてください。

```bash
npm install -g @masuidrive/procman
```

そして、[ticket.sh](https://github.com/masuidrive/ticket.sh)と組み合わせれば、AIエージェントとの開発がさらにスムーズになります。
